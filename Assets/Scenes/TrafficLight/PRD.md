# TrafficLight 红绿灯情境训练游戏需求文档

状态：待审核草案。日期：2026-10-08。本文记录首版产品需求，不作为游戏策划案（GDD）或技术设计文档。本文的项目路径均相对于 `Lumina` 项目根目录（`.`）。

“已确认”表示用户在需求讨论中明确提出或认可；待确认事项和策划建议分别列出，不能作为已批准的开发要求。术语见同目录的 [GLOSSARY.md](./GLOSSARY.md)。

## 1. 目标、用户与使用环境（已确认）

- **游戏目标**：通过道路与路口红绿灯情境，提供识别交通信号、按规则前进和停止的练习，作为面向孤独症谱系障碍儿童的干预研究原型。PRD 验收以功能和记录能力为依据，训练效果由后续实验评估。
- **训练重点**：规则识别与遵守，以及依据信号起步、停步。踏步频率控制走跑是核心交互方式。
- **使用方式**：成人在场组织的单人训练。儿童通过体感参与；研究人员或老师负责开始、暂停、结束训练以及导出数据。
- **输入环境**：沿用项目已有的摄像头与 MediaPipe 体感输入。儿童在现实中原地踏步，控制游戏角色前进。
- **产品取向**：重技术、轻交互，首版体量较小，围绕核心训练流程提供必要操作。

## 2. 首版核心功能（已确认）

| 编号 | 需求 | 可观察的行为 |
| --- | --- | --- |
| R01 | 道路与路口情境 | 场景包含可前进的道路，以及带交通信号灯的路口。参考素材只用于理解道路和信号情境，不要求复刻视频。 |
| R02 | 原地踏步控制前进 | 儿童开始有效踏步时，角色前进；停止踏步时，角色停止前进。 |
| R03 | 踏步频率控制走跑 | 使用踏步频率区分步行与跑动；达到阈值后进入跑动。具体阈值和速度在后续阶段确定。 |
| R04 | 红灯停、绿灯行 | 红灯要求儿童停止踏步并等待；绿灯允许通过踏步控制角色通行。 |
| R05 | 违规后的阻挡与回位 | 红灯时继续踏步，角色越过停止线并进入路口一小段后，出现阻挡反馈，随后角色返回当前路口停止线前的位置。 |
| R06 | 停步后解除阻挡 | 回位后，儿童持续踏步时保持阻挡，避免反复越线、回位；确认儿童实际停步后解除本次阻挡，绿灯时允许重新踏步通行。系统强制角色静止不能替代儿童实际停步。 |
| R07 | 成人训练操作 | 成人能够开始、暂停、结束训练，并导出实验数据。 |
| R08 | 实验数据记录 | 记录行为结果和过程指标，并按匿名儿童编号关联每次训练，支持比较同一儿童多次训练的表现。 |

交警、车辆或其他角色均是用户认可的阻挡反馈候选表现，具体选用对象、动作和呈现方式待策划阶段确定。“回位”指返回当前路口停止线前，不是返回整段道路的起点。

## 3. 实验数据需求（已确认的范围）

首版记录行为结果和过程指标，姿态关键点原始数据不纳入首版需求。

| 数据类别 | 记录内容 | 用途 |
| --- | --- | --- |
| 训练关联信息 | 匿名儿童编号、训练日期、可区分每次训练的记录标识 | 区分不同儿童及同一儿童的多次训练 |
| 规则遵守结果 | 违规次数及可定位违规发生时刻的记录 | 观察规则遵守情况 |
| 行为反应 | 起步反应时间、停步反应时间 | 比较儿童在相应情境中的反应表现 |
| 踏步过程 | 踏步频率及与训练过程对应的时间信息 | 观察运动输入及走跑控制过程 |
| 训练结果 | 完成情况，区分正常完成和提前结束 | 理解每次训练的数据背景 |

成人应能导出指定儿童或指定训练记录。导出数据应保留儿童与训练的关联关系，便于后续统计和比较。文件格式、指标计算方式及反应时间的起止事件尚未确认，不能直接作为已确定的统计口径。

## 4. 范围与约束（已确认）

- 首版沿用 MediaPipe，不使用深度信息作为控制依据；踏步频率是走跑切换依据。
- 首版聚焦道路、路口、交通信号、踏步控制、违规反馈、成人操作和实验记录。
- 当前只编写 PRD；审核完成后，GDD 和技术设计另行编写，不自动进入后续阶段。
- 保持现有社交情绪部分稳定。TrafficLight 的功能文件归入 `Assets/Scenes/TrafficLight`，脚本放在其 `Scripts` 中，其他专属资源按现有简单布局放置；第三方资源包放在 `Assets/ThirdParty`。暂不新建共用文件夹。

## 5. 首版验收清单（供审核）

以下条目将已确认需求转为可检查行为，审核后作为功能验收依据。具体数值和统计口径尚未确定的项目，需要在对应事项明确后补齐量化判定条件。

| 编号 | 验收场景 | 通过条件 | 对应需求 |
| --- | --- | --- | --- |
| A01 | 查看并运行道路场景 | 可沿道路前进，在路口看到交通信号灯 | R01 |
| A02 | 儿童踏步并随后停步 | 踏步时角色前进；实际停步后角色停止前进 | R02 |
| A03 | 改变踏步频率 | 在已确定的阈值两侧，角色分别表现为步行和跑动；控制不依赖深度信息 | R03 |
| A04 | 红灯下越线 | 出现阻挡反馈，角色返回当前路口停止线前，产生违规记录 | R04、R05、R08 |
| A05 | 回位后继续踏步，再实际停步 | 持续踏步时不能反复越线；实际停步后解除本次阻挡；仍为红灯时不能正常通行，绿灯时可重新踏步通行 | R04、R06 |
| A06 | 成人操作训练 | 可开始、暂停和结束；暂停期间角色不继续前进 | R07 |
| A07 | 同一儿童完成多次训练 | 每次记录可单独区分，且均关联同一匿名编号和各自训练日期 | R08 |
| A08 | 导出并核对记录 | 数据包含约定的行为指标与训练结果，儿童编号和训练关联准确；正常完成与提前结束可区分 | R07、R08 |

## 7. 待策划阶段确定

- 具体道路与关卡组织、路口数量、一次训练的长度及完成条件。
- 视角、角色与环境表现，是否呈现黄灯及其含义。
- 信号灯切换方式、时长与其他时间参数。
- 越线距离、回位表现、阻挡角色及提示表现。
- 走跑阈值、速度、难度及参数调整方式。
- 是否设置奖励、如何表现反馈。

## 8. 策划与需求建议（未确认）

- 阻挡反馈采用简短、清楚的表现，避免额外复杂操作。
- 识别不可用时暂停角色移动，并让成人能够识别当前问题。
- 将暂停、识别异常和中断时段与儿童行为结果分开记录，避免把技术问题统计为儿童错误。
- 优先采用便于后续统计的数据导出格式，例如 CSV；具体格式需审核后确定。
