# Lumina《游戏一》语义理解与 NPC 语音：技术选型依据（重写版）

> 版本：2026-10-13｜用途：帮助开发者决定**选哪个模型、用在何处、为何选择、放弃什么**。以下为候选方案比较，不是项目实测结论。

## 一、先给结论

**建议采用“两条独立技术线”：云端语言模型负责理解儿童说话，本地 TTS 模型负责制作 NPC 声音；Unity 根据确定的任务规则决定奖励、提示等级和播放哪句台词。**

- **语义 API 首选试验：豆包 Seed 系列中账户可用、支持结构化输出的低延迟型号；平行对照：通义千问 Qwen-Flash / Qwen-Plus 等支持结构化输出的型号。** 先通过相同的儿童表达测试集比较正确率、漏判、延迟、失败回退和价格，再定最终具体型号。不能仅凭品牌或“模型大”选型。
- **NPC 本地语音首选试听：Qwen3-TTS-1.7B-VoiceDesign 与 Fun-CosyVoice3-0.5B-2512 两者并行。** 前者突出“通过自然语言设计角色声线”，后者突出“参考声音固定角色音色，以及情绪、语速等控制”。哪一个音色更适合儿童友好的老师和同伴，需要听实际生成样本才能判断。
- **轻量保底：sherpa-onnx + MeloTTS 中文 ONNX。** 能作为轻量离线合成路径，但特定 `vits-melo-tts-zh_en` 只有一名说话人，不适合作为多角色声音的唯一方案。
- **关键架构选择：游戏的 NPC 台词已经预先写好，因此在开发阶段批量离线生成音频，Unity 游戏运行时直接播放文件。** 游戏不需要每次 NPC 开口时运行 TTS，更不需要 TTS 自己临时写台词。

## 二、项目真正需要模型解决什么

游戏任务包括自我介绍、问好、请求加入、帮助他人和回应感谢。交互的目标不是开放式闲聊，而是**识别儿童在当前任务中有没有表达出恰当意思**。

| 功能 | 输入与输出 | 谁负责 | 为什么需要 / 不需要 AI |
|---|---|---|---|
| 儿童说话转文字（ASR） | 麦克风音频 → 转写文本 | 独立的语音识别系统 | 文本语义模型不能直接听麦克风；儿童发音、噪声是主要风险。**本报告不替 ASR 选型。** |
| 理解儿童意思 | “我也想和你们玩” → `REQUEST_JOIN` | 云端语义模型 | 同一个意思有很多说法，简单关键词容易漏判 |
| 判断游戏进度 | 根据任务阶段、动作检测、语义结果 → L0/L1/L2/L3 | Unity 的状态机/规则 | 奖励必须可控、可审计，不能让生成式模型自由决定 |
| 选择 NPC 回复 | `REQUEST_JOIN` → 对应台词 ID | Unity 的台词表 | 台词已写好，不需要额外调用模型生成内容 |
| 生成 NPC 语音 | 固定台词 → WAV/OGG 音频 | 本地 TTS（制作期） | 需要老师、同伴的声音风格，又不想逐句真人录音 |
| 播放 NPC 声音 | 台词 ID → 音频文件 | Unity AudioSource | 播放现成音频比运行 TTS 模型更简单、稳定 |

**例子：** 儿童在场景三说“我能不能跟你们搭那个城堡呀？” → ASR 转文字 → 语义模型输出 `REQUEST_JOIN` → Unity 检查当前确实位于“主动请求加入”任务 → 判定本轮完成并给对应星星 → 播放早已做好的“当然可以啦！”音频。**语义模型不负责奖励，也不写这句回复。**

## 三、云端语义理解模型怎么选

### 3.1 要比什么：不是“聊天智商”，而是任务判定能力

| 选型指标 | 在本游戏中的具体价值 | 建议如何测 |
|---|---|---|
| 口语意图识别 | “嗨”“你好呀”“跟你玩行吗”等多种说法都能理解 | 同义改写、儿语、不完整句测试 |
| **不误判** | “我不想玩”“不要帮我”不能被识别为积极参与 | 否定、反问、模糊和拒绝样例 |
| 分槽位提取 | 自我介绍提取名字、年龄、爱好 | 分次说、纠正前一句、漏报一项 |
| 结构化返回 | Unity 能稳定读取 `intent`、`slots` 等字段 | JSON Schema 校验 + 异常响应 |
| 响应延迟/稳定性 | 儿童不应长时间等待 NPC 反应 | 实测端到端 P50/P95、超时率 |
| 成本与数据处理 | 长期使用成本、儿童文本处理边界 | 测试集单次平均花费、保留策略 |

### 3.2 可以选哪些模型

| 候选 | 为什么纳入 | 更适合的使用场景 | 需要警惕什么 |
|---|---|---|---|
| **豆包 Seed 系列：可用的轻量/低延迟型号** | 与原方案火山方舟接口方向一致；适合先做结构化意图提取原型 | 游戏运行时短句、较固定的意图类别 | 具体型号、账户开通、结构化输出支持和价格须逐一核对；不能把“某个型号支持”当成全系列支持 |
| **通义千问 Qwen-Flash 类** | 作为另一家 API 的低延迟/成本对照；百炼提供结构化输出能力 | 高频短句语义分类，预算敏感 | Flash 不意味着对儿童含混语句就足够准确；需实际对照 |
| **通义千问 Qwen-Plus 类** | 作为更强推理/复杂表达的质量对照 | 多轮自我介绍信息补全、间接表达、否定与纠错 | 可能增加时延和成本；若测试提升不明显就不值得使用 |
| **豆包 Seed 系列：更高能力型号** | 保持同一供应商环境下的模型能力对照 | 基准轻量模型处理不好复杂表达时 | 不能只依据参数量或营销等级判断收益 |

这里列的是**候选型号类别**，不是已经通过项目验收的具体版本。模型名称、可用性、价格在平台内变化，最终由账户可选型号和实测确定。

### 3.3 我建议如何作决定

1. 先用约 100～200 条带标准答案的表达建立小测试集，覆盖五类游戏任务；其中专门放入否定、沉默（ASR 空文本）、噪声转写错误、部分姓名年龄爱好，以及反问和模糊表达。
2. 先测两家低延迟型号；如果都能达到项目定义的意图识别要求，就选**错误少且成本/延迟更优**的那一个。
3. 如果轻量型号反复误判复杂表达，再让更强型号做**针对性回退**，而不是所有请求都用大模型。
4. 设置“未知/无法确定”输出，不能强迫模型二选一；API 超时或格式错误属于系统问题，**不扣儿童星星**。

建议返回格式示意（这是本项目设计，不是某厂商专属接口）：

```json
{
  "task_id": "scene3_request_join",
  "intent": "REQUEST_JOIN",
  "slots": {},
  "evidence": "我能不能跟你们搭城堡",
  "needs_clarification": false
}
```

**为什么不建议直接让大模型控制 Unity 流程？** 因为任务的 L0–L3、奖励和场景迁移已有明确逻辑。模型只负责给出“语义证据”，Unity 才是唯一能改变游戏状态的地方；这样失败可复现、结果可审计，也不会让同一句话在不同运行中莫名改变星星。

## 四、本地 NPC TTS 模型怎么选

### 4.1 你的实际需求

NPC 分老师、儿童同伴等多种角色；希望区分**性别感、年龄感、说话语气和情绪**。语音句子预先确定，所以排序应是：**角色声音是否合适与稳定 > 中文清晰度 > 风格控制 > 制作成本 > 合成速度**。运行时实时流式合成并非核心指标。

注意：性别/年龄感是听觉设计目标，并不意味着任何模型都有准确的 `gender=女`、`age=6` 数字控制参数。

### 4.2 TTS 候选对照

| 候选及版本 | 特别值得用的地方 | 最适合 Lumina 哪部分 | 局限与代价 | 推荐位置 |
|---|---|---|---|---|
| **Qwen3-TTS-12Hz-1.7B-VoiceDesign** | **根据文字描述创建声线**，可尝试描述“温柔的成年女教师”“清亮、友好的儿童感声音” | 在制作期探索、挑选不同 NPC 的角色声音 | 描述不等于精确锁定年龄，重复生成的一致性需验收；本地资源开销更高 | **首选试听 A** |
| **Fun-CosyVoice3-0.5B-2512** | 参考声音/音色复用，支持情绪、语速等指令类控制 | 需要让同一老师在很多句台词中保持接近的音色，并有温柔、开心等变化 | 需要质量良好、获授权的参考音频；Windows 环境兼容性需测试 | **首选试听 B** |
| **Qwen3-TTS-12Hz-1.7B-CustomVoice** | 使用官方预置声线，部分风格可通过指令控制 | 不想录制参考音色、希望选现成角色声线 | 声线范围受预设集合限制；不能等同于自由创造新音色 | 优先备选 |
| **Qwen3-TTS-12Hz-0.6B-CustomVoice** | 比 1.7B 小；可使用预设音色 | 本地资源有限、角色声音要求不太复杂 | 官方型号能力与 1.7B 不完全相同，不能默认它具备相同自由指令控制 | 轻量备选 |
| **CosyVoice-300M-SFT / Instruct** | 更旧、更小的预设说话人/风格指令路线 | 已有符合要求的预设音色时 | 不能把 CV3 的全部新特性直接套到 300M 系列上 | 次级备选 |
| **sherpa-onnx + `vits-melo-tts-zh_en`** | ONNX 离线部署路径，模型文件约 163 MB | 快速验证 Unity 音频生产流程、低资源基础中文配音 | 此具体模型只有 **1 个说话人**，多角色差异化不足 | 保底方案 |
| **F5-TTS** | 参考语音驱动的音色模仿，可作为额外试听基线 | 有合规参考录音时做音色对比 | 官方预训练权重存在非商业用途许可限制，未来商业化需单独评估 | 非第一梯队 |

### 4.3 不同需求下该选谁

- **没有现成声音素材，想直接描述“老师声音/小朋友声音”：先试 Qwen3-TTS VoiceDesign。** 这是其最突出的差异化价值。
- **已经有满意且获授权的配音样本，希望很多句台词保持同一个角色的音色：先试 CosyVoice3。** 也可把 Qwen3-TTS Base 的参考音频克隆路线作为对照，但 Base 与 VoiceDesign 是不同型号，别混为一谈。
- **只是想让系统先开口、没时间选角色声音：用预置声音型号或轻量 ONNX 先通功能。** 不必在早期就投入复杂音色工程。
- **希望语气特别明确（鼓励、惊喜、安慰）：两大候选都要用相同台词做试听。** 不要把“支持风格指令”当成“每条音频一定表现自然”的证明。

### 4.4 本游戏的实际用法

```text
【制作阶段】
预设台词文本 → 选择 NPC 声线 → 本地 TTS 批量生成 → 人工试听/修正 → 音频文件 + 台词表
                                                                      │
【游戏运行】                                                        加载音频
儿童说话 → ASR → 云端语义模型 → Unity 按规则选定台词 ID ────────────────────→ 播放
```

建议为每条音频记录 `scene_id / task_id / line_id / npc_id / text / voice_version / audio_path / review_status`。例如场景二“你好呀！很高兴认识你！”只生成一次；改变台词或角色声线时，才重新合成该条文件。

**例外：** 如果某条 NPC 台词必须念出本轮新提取的姓名、年龄或爱好，那不再是完全固定的音频。优先使用有限占位语音、预先录入并离线生成个性化版本；若必须任意实时读出，再单独论证运行期 TTS，不能把这一特殊需求扩大到全游戏。

## 五、落地方案与验证门槛

### 5.1 分阶段实施

| 阶段 | 交付内容 | 决策点 |
|---|---|---|
| P0：固定规则先跑通 | Unity 用模拟意图触发正确台词、奖励和流程 | 无需接入任何大模型，就能验证游戏逻辑 |
| P1：语义 API 对照 | 同一测试集比较豆包轻量型号、Qwen-Flash 类及必要的强模型 | 确定低误判且满足延迟预算的模型 |
| P2：NPC 声线试听 | Qwen3-TTS VoiceDesign vs CosyVoice3，各做教师和两类儿童同伴样音 | 由真人评审选清晰、自然、角色一致的声音 |
| P3：批量生产 | 预生成全部固定台词音频，导入 Unity | 发布时默认不附带 TTS 推理服务 |
| P4：联合验收 | 实际麦克风→ASR→API→Unity→音频反馈，测试延迟和失败路径 | 检查儿童真实语音、断网、误判和异常回退 |

### 5.2 必须避免的误区

1. **TTS 不是 ASR，也不是语义理解。** 本地 NPC 发声不能证明儿童说话识别已经解决。
2. **API 格式正确不等于意思判对。** 结构化 JSON 只降低集成错误，不保证儿童口语理解正确。
3. **“有年龄/性别控制”不能凭主观指令声称精确。** 需建立角色音色试听标准。
4. **制作期离线合成 ≠ 玩家机器运行本地 TTS。** 本方案让游戏运行端只播放音频，规避与 Unity/MediaPipe 争夺资源。
5. **不应未经测试宣称儿童语音识别准确率、干预效果、Windows 兼容性或实时性能。**
6. **儿童隐私**：云端语义 API 会收到经 ASR 得到的文本；尽量去标识化、减少上下文发送；密钥由可信服务端管理。参考音色必须具备使用授权。

## 六、最终推荐表

| 任务 | 目前建议 | 为什么 | 何时换方案 |
|---|---|---|---|
| 短句语义理解 | **豆包低延迟型号 vs Qwen-Flash 做 A/B** | 游戏更看重否定识别、明确意图、延迟和成本 | 错误率高时升级更强型号，或增加高风险表达专用规则 |
| 复杂信息补全 | **Qwen-Plus 或豆包较强型号作对照** | 自我介绍跨轮信息累计可能比简单打招呼难 | 如果轻量模型通过验收，就不需要强模型 |
| 教师/儿童 NPC 创作新声线 | **Qwen3-TTS VoiceDesign** | 可直接用文字描述尝试构造不同角色声音 | 音色不稳定或不自然时换参考音色路线 |
| 保持 NPC 音色一致 | **CosyVoice3** | 参考音色路线适合多句台词统一人设 | 若预设声线已足够，就简化为 CustomVoice |
| 基础离线语音保底 | **sherpa-onnx + MeloTTS** | 部署路径相对轻量 | 不满足多角色区分时退出主方案 |
| 游戏运行时 | **Unity 播放预生成音频** | 最符合已固定台词需求，减少运行期复杂度 | 仅遇到真正动态台词时再增加实时 TTS |

**最终选型尚未完成。** 现在可以确定的是技术架构和候选短名单；真正的模型胜出必须来自同一测试集与同一组试听材料的比较，不能仅靠官方宣传。
