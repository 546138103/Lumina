# 技术选型依据：语义 API 与本地 NPC 语音

核查日期：2026-10-13。本文查阅官方文档、官方模型卡与源码；没有安装模型、调用收费 API、合成试听或测量运行性能。所有推荐均为待验证的技术方案，不构成对儿童语音准确率或干预效果的承诺。

## 1. 本次确定的边界

用户确定语义理解接入云端 API，NPC 语音采用本地模型。最新补充：NPC 台词预先设置，模型只负责将既定文字合成为声音；希望配置性别、年龄感、语调等角色声音特征。因此，优先流程是“制作期本地合成、试听和保存，游戏运行时选择预设台词并播放音频”。运行时无需让语言模型生成 NPC 回答，也无需为全部固定台词实时启动 TTS。

本文以豆包／火山方舟作为语义 API 参考，以 CosyVoice 为可控制音色的本地 TTS 候选；这些选型尚未经项目实测。语义判断与台词选择分开：API 返回表达意图与提取信息，Unity 的确定性规则选择台词、处理任务和评分。

本地 TTS 仅表示声音合成在本机完成；语义请求中的文字和必要对话上下文仍会发送至云端。若语义输入来自儿童说话，还必须有独立的 ASR 环节；TTS 不负责听懂儿童。

## 2. 火山方舟语义 API 的可用依据

方舟数据面 Base URL 为 `https://ark.cn-beijing.volces.com/api/v3`，Chat 入口为 `POST /chat/completions`；API Key 通过 `Authorization: Bearer ...` 传递。接口也有 Access Key 路线，但项目原型采用 API Key 即可；模型 ID 需在实际账户中开通并核对。[官方 Base URL 与鉴权](https://docs.volcengine.com/docs/ark/base-url-and-authentication?lang=en)

Chat API 通过 `response_format.type = json_schema`、`json_schema.schema` 与 `strict = true` 定义固定输出格式；`json_object` 仅保障合法 JSON，不等同于遵循自定义字段结构。Responses API 使用 `text.format`，两种接口的请求结构不能混用。[Chat API 参数](https://docs.volcengine.com/docs/ark/chat-api?lang=zh)、[结构化输出说明](https://docs.volcengine.com/docs/ark/structured-output-beta?lang=zh)、[Responses API 参数](https://docs.volcengine.com/docs/ark/create-model-responses-api?lang=zh)

官方目前仍将结构化输出标记为 beta，并提示服务可用性波动；在线推理的 TPM 保障包模式不支持此能力。实现前要确认所选模型和调用模式支持 Schema，不能只因“豆包支持”便假设全部版本都支持。[官方能力限制](https://docs.volcengine.com/docs/ark/structured-output-beta?lang=zh)

项目建议输出 `intent`、`evidence`、`slots`、`needs_clarification` 等有限字段。Schema 控制的是结构，无法证明判断正确；Unity 仍需检查意图允许集合、原文依据、任务编号和迟到结果。拒绝、不确定、识别失败分别处理，不能由 API 自报置信度直接决定星星。以上是本项目的工程设计建议，不是服务商提供的游戏功能。

API Key 不应写入场景资源、Git 或游戏安装包；发布版由可信服务端保管密钥并转发最少必要文本。网络失败、Schema 错误和限流应返回明确的基础设施状态，暂停任务计时或走已设计的回退，不算儿童未完成。

## 3. 本地 TTS 主候选：CosyVoice

### 3.1 模型版本与能力

官方仓库 `FunAudioLLM/CosyVoice` 目前重定向至 `QwenAudio/CosyVoice`，README 主推 `Fun-CosyVoice3-0.5B-2512`。CV3 官方列出中文等 9 种语言、参考声音的零样本音色、文本输入／音频输出双流，以及情绪、速度、音量等指令控制。这里无需启用流式，固定台词完整合成更方便试听验收。[官方仓库](https://github.com/QwenAudio/CosyVoice)

官方模型卡标明该 CV3 权重为 Apache-2.0，仓库代码也采用 Apache-2.0。`CosyVoice-300M-SFT`、`CosyVoice-300M-Instruct` 模型卡亦标明该许可。旧模型卡正文当前复用了 CV3 介绍，因此不能把正文中的全部 CV3 能力套用到旧模型；调用方式应以对应源码和示例为准。[CV3 模型卡](https://huggingface.co/FunAudioLLM/Fun-CosyVoice3-0.5B-2512)、[SFT 模型卡](https://huggingface.co/FunAudioLLM/CosyVoice-300M-SFT)、[Instruct 模型卡](https://huggingface.co/FunAudioLLM/CosyVoice-300M-Instruct)、[仓库许可](https://github.com/QwenAudio/CosyVoice/blob/main/LICENSE)

### 3.2 性别、年龄和语调怎样落到真实能力

应区分“角色配置”与“模型参数”。`gender`、`age_band` 可以作为项目音色库检索标签，但官方公共推理入口未提供这两个独立参数，不能承诺输入“年龄 6 岁”就能准确生成对应年龄声音，也不能承诺有独立的数值 `pitch`／语调滑块。[实际公共入口](https://github.com/QwenAudio/CosyVoice/blob/main/cosyvoice/cli/cosyvoice.py)

- **预设音色路线**：300M-SFT 通过 `inference_sft` 指定 `spk_id`，示例先调用 `list_available_spks()` 查询，而非任意填写声音名称；300M-Instruct 使用 `inference_instruct`，同时传 `spk_id` 和声音风格描述。实际可用说话人以下载的权重为准。[官方调用示例](https://github.com/QwenAudio/CosyVoice/blob/main/example.py)
- **参考音色路线**：CV3 通过参考音频或已注册的 `zero_shot_spk_id` 保持角色身份；可以为成人教师、同伴等分别建立经过授权和试听的音色档案。性别和年龄感主要通过选择合适参考声音实现，而不是每句重新“改年龄”。注册音色与模型能力不等同于获取了参考录音的使用授权。[音色注册与入口源码](https://github.com/QwenAudio/CosyVoice/blob/main/cosyvoice/cli/cosyvoice.py)
- **情绪和节奏路线**：CV3 官方指令列表含开心、伤心、生气、快／慢语速和柔和／响亮音量示例。其他“温柔、鼓励、像儿童”等风格可作为试验描述，必须试听，不视为保证；疑问句上扬、逐词重音等控制也需实测。[官方指令示例](https://github.com/QwenAudio/CosyVoice/blob/main/cosyvoice/utils/common.py)

概念请求示例（映射官方 `inference_instruct2` 入口，不是已实现的 HTTP API 或可执行脚本）：

```json
{
  "tts_text": "你愿意和我们一起搭积木吗？",
  "instruct_text": "You are a helpful assistant. 请非常开心地说一句话。<|endofprompt|>",
  "prompt_wav": "经过授权并已验收的同伴音色参考录音",
  "zero_shot_spk_id": "",
  "stream": false,
  "speed": 1.0,
  "text_frontend": true
}
```

`inference_instruct2` 真实接收这些参数；返回的是带 `tts_speech` 的迭代结果，采样率从模型实例读取。参考录音是本地资源，不是云端上传。零样本文字／音频对齐模式使用 `inference_zero_shot`，其 `prompt_text` 应匹配参考录音内容；不要把两种模式参数混用。[入口源码](https://github.com/QwenAudio/CosyVoice/blob/main/cosyvoice/cli/cosyvoice.py)、[CV3 示例](https://github.com/QwenAudio/CosyVoice/blob/main/example.py)

`speed` 支持非流式合成的速度变化，源码明确限制不能随意用于流式变速；其实现调整声学特征长度，不代表任意音高编辑能力。[速度实现](https://github.com/QwenAudio/CosyVoice/blob/main/cosyvoice/cli/model.py)

### 3.3 离线资源、Windows 与性能边界

源码依据显示需要完整权重、配置、文本 tokenizer、说话人／语音 tokenizer 资源及 Python 推理依赖；模型目录不存在时会尝试 `snapshot_download`，所以要在断网前准备并校验本地资源，不能靠缓存偶然命中。[模型装载源码](https://github.com/QwenAudio/CosyVoice/blob/main/cosyvoice/cli/cosyvoice.py)

README 的基础示例采用 Python 3.10，额外 `ttsfrd` wheel 与容器示例走 Linux 路线；`ttsfrd` 可选，不安装时走默认文本处理。源码有 CPU／CUDA 分支，但不证明该电脑原生 Windows 安装、所有依赖及长时批量合成已验证。先尝试原生 Windows 基础推理；若依赖不兼容，再评估本机 WSL2／Linux 环境，仍属于本地，需另行安排环境修改。[安装说明](https://github.com/QwenAudio/CosyVoice)、[装载源码](https://github.com/QwenAudio/CosyVoice/blob/main/cosyvoice/cli/cosyvoice.py)

官方“低至 150 ms”与 TensorRT-LLM 加速是上游能力／环境声明，不能作为 Lumina 在普通 Windows、CPU或与 Unity 同时运行的 SLA。本文不指定未经测试的最低显存或实时吞吐。固定台词预生成使玩家设备只需播放音频，减少与 MediaPipe、Unity 的资源争用；这属于项目架构推论。

## 4. 轻量备选：sherpa-onnx + MeloTTS 中文 ONNX

`vits-melo-tts-zh_en` 官方 ONNX 示例支持中英、1 个说话人，模型文件约 163 MB、采样率 44100 Hz，需要模型、词典和 token 等资源；英文词受词典范围限制。单音色适合低资源验证，但不满足多角色年龄和性别音色库需求，不应作为与 CV3 同等可控的替代。[官方模型与资源说明](https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/vits.html)

sherpa-onnx 官方提供 Windows 构建／安装说明，运行时采用 Apache-2.0；原始 MeloTTS 中文模型卡与代码采用 MIT。具体发行包仍需保存其 LICENSE；运行时许可不能替代模型许可。[Windows 文档](https://k2-fsa.github.io/sherpa/onnx/install/windows.html)、[运行时许可](https://github.com/k2-fsa/sherpa-onnx/blob/master/LICENSE)、[中文模型卡](https://huggingface.co/myshell-ai/MeloTTS-Chinese)、[MeloTTS 许可](https://github.com/myshell-ai/MeloTTS/blob/main/LICENSE)

MeloTTS 项目宣称可 CPU 实时推理，但 sherpa 官方同一模型的树莓派示例并非实时；硬件、实现和输入文本不同，不能移植数字。选它的理由是可作为 CPU／Windows 部署试验，实际速度与试听质量仍需测量。[原项目说明](https://github.com/myshell-ai/MeloTTS)、[ONNX 模型测试](https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/vits.html)

## 5. 项目建议与待验证项

建议先用 CV3 为教师和同伴各做一套音色，再将已确定的任务提示、问候、感谢与拒绝回应批量合成。保存台词 ID、角色 ID、音色版本、模型版本、参考音频标识、风格指令、速度、文件哈希与试听状态；文本或音色配置改变时仅重新生成受影响音频。发布版优先只携带已验收音频和台词索引。

语义 API 返回意图后，由 Unity 查找预设回应 ID，播放对应音频；不把儿童原话直接交给 TTS，不让 TTS 决定台词内容。自我介绍若有个性化台词，可在活动前生成并验收，再开始活动；具体需求仍以原案与用户确认范围为准。

验证需要分别覆盖：API 的否定、模糊表达、多轮信息累计及格式／超时回退；本地 TTS 的漏字、重复、数字姓名发音、角色音色一致性、情绪强度、音量与试听耗时；完整游戏的播放结束、任务计时、取消后停止音频和旧结果过滤。未完成这些验证前，不应写“已支持 Windows 实时”“准确识别儿童意思”或“已达到干预效果”。
