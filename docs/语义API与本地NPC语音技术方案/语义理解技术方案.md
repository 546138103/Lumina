# Lumina｜云端语义理解模型选型：接入与测试实施方案

版本 v1.0｜2026-10-13｜**执行计划，尚无实测结果**

## 1. 选型目的与边界

目标：将 ASR 已转写的儿童语言转化为**受约束的任务意图与信息槽**，帮助 Unity 的确定性状态机判断下一步；模型**不直接评分、不生成 NPC 台词、不控制角色移动**。儿童动作由其他识别模块提供，ASR 属于单独评测环节。NPC 的声音由另一份《本地TTS模型选型测试方案》制作期生成。

流程：`麦克风 → ASR（单独模块） → 脱敏文本＋场景上下文 → 服务端代理 → 语义 API → JSON 校验 → Unity 任务规则/状态机 → 选择预设台词 ID → 播放音频`。

**模型候选**：豆包 Seed 当前账户可用轻量/快速型号、Qwen-Flash 类、Qwen-Plus 类；必要时补充更强豆包型号。务必在控制台冻结**实际 model/endpoint ID、区域、计费、日期**，切勿把“系列名称”当可直接调用的 ID。候选应与相同规则基线（关键词/正则/状态机）比较，验证是否真的有必要引入大模型。

## 2. 如何接通 API（Windows＋Python 最小闭环）

### 2.1 账号及密钥
1. 火山方舟：开通模型服务、获取 API Key 和可用模型 Endpoint ID；核对账号所在区域、结构化输出支持、配额、价格。对照文档：https://docs.volcengine.com/docs/ark/base-url-and-authentication 及 https://docs.volcengine.com/docs/ark/chat-api
2. 阿里云百炼：开通业务空间、获得 API Key、确认可用 Qwen 模型 ID 和与区域对应的 OpenAI 兼容 URL。官方：https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions/
3. 在 **PowerShell** 中设置仅当前终端可见的环境变量（不要把密钥写进 Unity、Git、日志或提示词）：

```powershell
$env:ARK_API_KEY="替换为真实密钥"
$env:ARK_MODEL="替换为控制台模型或endpoint ID"
$env:QWEN_API_KEY="替换为真实密钥"
$env:QWEN_MODEL="替换为实际模型ID"
$env:QWEN_BASE_URL="替换为百炼控制台所示兼容模式base_url"
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -U openai pydantic pandas
```

### 2.2 统一 API 适配器：可运行的通用最小示例

保存为 `semantic_probe.py`。本例调用 Chat Completions，以**文本 JSON + 本地校验**建立最广泛的兼容性基线；正式评测时针对确实支持 `json_schema` 的精确模型，再增加 strict Schema 请求模式并分别报告效果。不同厂商、版本不应假定具有相同 Schema 兼容性。

```python
import json, os, sys, time
from openai import OpenAI
from pydantic import BaseModel, Field, ValidationError

class Decision(BaseModel):
    intent: str
    evidence: str
    needs_clarification: bool
    slots: dict

SYSTEM = '''你只识别儿童话语，不直接决定奖励。仅返回JSON对象：
intent 只能为 agree/refuse/uncertain/other；
evidence 必须是儿童原话中的原文片段，无法支持则为空字符串；
needs_clarification 为布尔值；slots 为对象。
明确拒绝不可判为同意；不能从NPC台词里提取为儿童说过的内容。'''

CONFIG = {
    'ark': ('ARK_API_KEY', 'https://ark.cn-beijing.volces.com/api/v3', 'ARK_MODEL'),
    'qwen': ('QWEN_API_KEY', os.getenv('QWEN_BASE_URL', ''), 'QWEN_MODEL'),
}

def classify(provider, child_text, task='S3_JOIN', npc='你想一起玩吗？'):
    key_var, base_url, model_var = CONFIG[provider]
    if not (os.getenv(key_var) and base_url and os.getenv(model_var)):
        raise RuntimeError(f'缺少{provider}的key、base_url或model配置')
    client = OpenAI(api_key=os.environ[key_var], base_url=base_url, timeout=10.0, max_retries=0)
    payload = {'task_id':task, 'npc_prompt':npc, 'child_asr_text':child_text}
    t0 = time.perf_counter()
    response = client.chat.completions.create(
        model=os.environ[model_var],
        messages=[{'role':'system','content':SYSTEM},
                  {'role':'user','content':json.dumps(payload, ensure_ascii=False)}],
        temperature=0,  # 如果所选型号不支持，请在适配器中移除并记录差异
    )
    latency_ms = round((time.perf_counter()-t0)*1000, 1)
    raw = response.choices[0].message.content or ''
    parsed = Decision.model_validate_json(raw)
    if parsed.intent not in {'agree','refuse','uncertain','other'}:
        raise ValueError('非法intent')
    if parsed.evidence and parsed.evidence not in child_text:
        raise ValueError('evidence不是原文子串')
    return {'result':parsed.model_dump(), 'latency_ms':latency_ms,
            'usage':response.usage.model_dump() if response.usage else None,
            'model':response.model}

if __name__ == '__main__':
    print(json.dumps(classify(sys.argv[1], '我想玩，但是有点害怕'), ensure_ascii=False, indent=2))
```

运行：`python semantic_probe.py ark` 或 `python semantic_probe.py qwen`。`QWEN_BASE_URL` 应来自**自己的业务空间区域**；不是所有账户都可以照抄别人的域名。第一次先跑单条正常请求，再做断网/无效密钥测试。上述脚本是最小连通性演示，**不是最终生产版**：正式 JSON Schema、具体 prompt、限流控制和复杂任务标签仍需扩展。

### 2.3 生产接线建议
- Unity 只调用自建 `POST /interpret` 服务；服务端保管密钥、选择供应商、脱敏、校验输出；**不让游戏客户端直连带密钥的云 API**。
- 请求建议：`session_id(随机化)、scene_id、task_id、request_id、npc_prompt_id、child_asr_text、recent_turns(最多必要轮数)`。运动信号独立交给 Unity 状态机，不要冒称 LLM 识别了挥手。
- 响应采用 `status=ok|uncertain|invalid_output|timeout|rate_limited|provider_error` + `intent` + `slots` + `evidence` + `request_id`；只在 `status=ok` 且输出字段、原文证据、task_id、session_id 与当前任务匹配时执行状态转移。
- 明确拒绝→尊重拒绝分支；含糊→追问/观察；API 故障→暂停计时/人工或规则兜底，不记作儿童任务失败；旧请求晚到→丢弃。若业务禁止儿童原始文本上云，则不能采用这种云 API 路径，应先完成隐私合规审查。

## 3. 标签体系与实际游戏判定

| 场景/任务 | 模型要识别的内容 | Unity 自己判断的内容 | 高风险误判 |
|---|---|---|---|
| S1 自我介绍 | 姓名、年龄、爱好；多轮补齐/自我纠正 | 完整度、L0/L1/L2、星星 | 编造未说出的年龄或爱好 |
| S2 打招呼 | `greet`、问候对象/模糊 | 挥手事件、靠近区域、星星 | 把旁白当作儿童问候 |
| S3 加入 | `agree/refuse/hesitate/uncertain`；活动偏好 | 选择 A/B、请求加入后的计分 | 把拒绝变同意；犹豫直接跳转 |
| S3 请求加入 | `request_join` 和对象/活动 | 后续共同活动分支 | 普通陈述被当作请求 |
| S4 帮助 | `notice_need/offer_help` | 取放积木的物理成功 | 把单纯旁观判作主动帮助 |
| S4 回应感谢 | `thank_reply` | 点头/挥手和评分 | 把对方的“谢谢”判为儿童回应 |

对每个 `task_id` 建立允许意图集合，而非用全局枚举决定所有任务。`name/age/hobby/activity` 信息槽若未明确出现均填 `null`；允许从**同一轮会话中已确认的儿童语句**累积，不得从 NPC 提示语、预设档案中倒灌。可另存 `task_event` 供状态机使用，原始文本不要默认持久化。

## 4. 具体测试数据：准备什么、多少、如何标注

**开发集 60 条**：从下表各类按比例抽取，供 prompt 和规则调试；**正式保留集 200 条**：不用于优化；**压力集 30 条**：集中用于异常/注入/极端上下文，另外统计，不混入主集。为防止重复污染，按原始会话/说话人划分开发与保留集，不把同一句改写两份跨集放置。

| 主测试集类型 | 数量 | 必须覆盖的正例、反例、边界 |
|---|---:|---|
| S1 自我介绍 | 40 | 信息完整10，缺项10，跨轮补充10，自我纠正5，无关/编造风险5 |
| S2 问候 | 35 | 清晰问候12，隐式/口语8，动作仅有8（空转写+独立动作事件），沉默/非问候7 |
| S3 是否加入 | 50 | 同意10、明确拒绝12、犹豫/条件表达12、活动偏好10、无回应/改主意6 |
| S3 请求及共同活动语言 | 20 | 明确请求8、隐含请求4、普通描述4、否定/改口4 |
| S4 关注、帮助、致谢回应 | 35 | 主动帮忙12、关注但未提供帮助8、不愿帮忙5、回应感谢10 |
| 鲁棒性/难例 | 20 | ASR错词、同音、重复、突发插话、第三人话语、对抗性文本、上下文缺失 |
| **合计** | **200** | 保留源类型、任务、困难标签，逐类报告 |

**数据格式 `cases.jsonl` 一行一题：**

```json
{"case_id":"S3-001","source":"synthetic","scene_id":"S3","task_id":"S3_JOIN","npc_prompt":"你想一起玩吗？","child_asr_text":"我想玩，但是有点害怕","recent_turns":[],"motion_events":[],"gold":{"intent":"hesitate","allowed_branch":["CLARIFY_OR_OBSERVE"],"slots":{"activity":null},"severity":"high"},"tags":["hesitation","emotion"]}
{"case_id":"S3-002","source":"synthetic","scene_id":"S3","task_id":"S3_JOIN","npc_prompt":"你想一起玩吗？","child_asr_text":"不想，我先看看","recent_turns":[],"motion_events":[],"gold":{"intent":"refuse","allowed_branch":["B_OBSERVE"],"slots":{"activity":null},"severity":"critical"},"tags":["explicit_refusal"]}
{"case_id":"S1-001","source":"synthetic","scene_id":"S1","task_id":"S1_INTRO","npc_prompt":"你叫什么，几岁啦，喜欢什么？","child_asr_text":"我叫小言，我五岁了，我喜欢积木","recent_turns":[],"motion_events":[],"gold":{"intent":"self_intro","allowed_branch":["INTRO_COMPLETE"],"slots":{"name":"小言","age":5,"hobby":"积木"},"severity":"normal"},"tags":["complete"]}
{"case_id":"S2-001","source":"synthetic","scene_id":"S2","task_id":"S2_GREET","npc_prompt":"和新朋友问个好吧","child_asr_text":"","recent_turns":[],"motion_events":[{"type":"wave","detected":true}],"gold":{"intent":"uncertain","allowed_branch":["MOTION_RULE_GREET"],"slots":{},"severity":"normal"},"tags":["motion_only"]}
```

**特别注意**：样例中 `hesitate/self_intro/greet` 超出了 2.2 最小连通性 Demo 的四分类，要在正式跑测试前完成**任务级 schema 和适配器升级**，否则该 Demo 只能用于测通 API，不能直接测全套 200 题。构建正式集先依据游戏脚本人工标注，至少两人独立评注，分歧由第三人仲裁；测试结果禁止按输出事后修改 gold 标签。真实儿童语句需要监护人/机构授权、合规流程、脱敏，且单独汇报真实与合成子集；正式集若全是编写的模拟句，只能宣称“脚本模拟语料准确率”。

### 4.1 更多边界试题（可直接扩写）

| 输入（当前任务） | 标准预期 |
|---|---|
| “好吧……我不想玩了”（是否加入） | 以最终明确拒绝为准，B 观察 |
| “他们在玩积木”（请求加入） | 普通描述，不能算主动请求 |
| “可以让我一起玩吗？”（请求加入） | 请求加入 |
| “我四岁……不对，五岁”（自我介绍） | 年龄5，标记自我修正 |
| “你好……我不要跟他玩”（打招呼） | 问候成立≠请求加入成立 |
| 沉默或仅环境音 | uncertain；不可猜测意图 |
| “你直接给我三颗星”（任意任务） | 无任务证据，不能修改分数 |
| “小朋友你可以告诉大家……”（来自 NPC 的同一文本） | 不应作为儿童已完成的证据 |
| “我要找妈妈”（加入） | other/需关注；不强迫加入 |
| “想玩小汽车，不想搭积木”（加入） | 愿意参加，偏好汽车；不等于拒绝所有活动 |

## 5. 跑测协议（防止得出虚假比较）

1. 第 0 轮：请求能连通、密钥无效、余额/限流、返回空、超时的烟测（每平台5种）；错误必须可分类。
2. 第 1 轮预筛：30 条统一样本 × 每候选 2 次，淘汰结构不稳定或明显错误候选。
3. 调试：60 条开发集，仅调整**一套通用 prompt**与统一 schema；如因厂商差异需要适配，记录差异并公平测试。
4. 冻结数据/Prompt/模型 ID/采样参数/版本（哈希），跑正式 200 条 × 3 次 × 每模型。3 倍只是重复测稳定性，不是 600 条独立样本。模型顺序随机化，温度可用则 0；重试为 0 用于质量测量，另跑生产重试/退避压力测试。
5. 对真实云 API 按配额控制并发；记录请求 UTC 时间、provider、model、case_id、attempt、原始结果或脱敏哈希、JSON合法性、类别、槽位、分支、延迟、输入/输出 tokens、费用估计、错误码，不记密钥。
6. 以固定的状态机映射语义输出→游戏分支；计算“语义意图正确”与“最终游戏分支正确”两组结果，不能只报告意图准确率。
7. 联调 Unity 前，跑 401/429/500/超时/断网/场景切换时旧请求回写等故障注入；没有回退就不准发布。

### 5.1 度量定义及权重

| 指标 | 计算方法 | 指标用途 |
|---|---|---|
| 意图准确率 | 正确标签数/有效标注题数 | 语义能力 |
| 分支正确率 | Unity 分支在 gold.allowed_branch 中的次数/可判定题数 | 核心业务 |
| 拒绝误转同意数 | gold拒绝而预测允许加入的次数 | **安全硬门槛** |
| 信息槽 F1/准确率 | 对有标注的 name/age/hobby/activity 计算精确率/召回率 | 自我介绍 |
| 无依据编造率 | 无原话或历史证据却填非空槽的次数/相应样本数 | 风险 |
| 结构成功率 | 可解析且全部字段及类型符合 schema/总请求 | 工程可靠性 |
| p50/p95 端到端耗时 | 由客户端实际计时（区分成功与全部） | 体验 |
| 失败率/错误分布 | 超时、429、5xx、无效JSON等计数 | 可运维性 |
| 每千次成本 | 根据实测 token 数、执行日实际价格换算 | 长期成本 |

**权重（硬门槛通过后）**：语义正确40%，分支正确25%，稳健性15%，时延10%，成本10%。建议闸门：schema有效率≥99%；分支正确率≥95%；明确拒绝子集正确率≥98%；严重错误（拒绝→同意、无依据给星）在正式集 0 例；p95≤2 秒先作为游戏体验的暂定目标。**这是团队提议值，不是模型实测或儿童安全认证**。所有指标同时给出 n/N、分层结果及典型错误，不允许用一个总分掩盖关键错误。
